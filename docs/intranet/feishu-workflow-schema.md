# 飞书建联主库契约（首期）

更新日期：2026-07-15。表格 token、字段 ID、权限和网络状态均为易变信息，接入前必须重新检查。

## 产品边界

- 飞书是团队任务、审批和状态的权威主库。
- Electron 应用负责蒲公英采集、达人复核、批次准备和本地故障恢复。
- 蒲公英邀约、邮件、小蜜蜂微信申请的实际发送必须经过人工审批。
- 首期不接发送结果和回复结果，但保留 `send_events`、`reply_events` 两类只追加事件。

## 六张表

| 表 | 主键 | 首期用途 |
| --- | --- | --- |
| `tasks` | `task_id` | 任务名称、负责人、筛选条件、任务状态 |
| `task_creators` | `task_creator_id` | 任务内达人、复核结论、渠道、跟进状态 |
| `execution_batches` | `batch_id` | 渠道、人数、话术版本、审批及执行状态 |
| `approvals` | `approval_id` | 审批指纹、审批人、审批时间和状态 |
| `send_events` | `event_id` | 预留发送成功/失败结果，只追加不覆盖 |
| `reply_events` | `event_id` | 预留回复状态和摘要，只追加不覆盖 |

字段白名单由 `desktop-app/lib/feishu_contracts.js` 维护。飞书实际字段 ID 在部署配置中映射，禁止把 app secret、token 或 cookie 写入仓库。

## 审批不变量

审批指纹必须覆盖：

1. 执行渠道。
2. 达人收件人集合及目标账号。
3. 发送标题和正文/好友申请话术。
4. 小蜜蜂任务微信、智能备注规则和标签。

收件人、渠道、话术或执行账号发生变化后，旧审批不得继续使用。只有 `approved` 且指纹仍匹配的批次可以生成小蜜蜂执行文件或触发未来发送适配器。

## 同步接口

本地统一输出以下事件信封：

- `upsert_task`
- `upsert_task_creator`
- `upsert_execution_batch`
- `upsert_approval`
- `append_send_event`（预留）
- `append_reply_event`（预留）

每个信封包含 `eventId`、`eventType`、`occurredAt`、`status` 和 `payload`。同步实现必须使用稳定业务 ID 做幂等更新；发送和回复事件只能追加。

## 小蜜蜂首期映射

| 内部字段 | 小蜜蜂字段 |
| --- | --- |
| 微信号，必要时手机号兜底 | `微信号码` |
| 智能备注规则 | `智能备注` |
| 微信分组标签 | `标签` |
| 已审批好友申请话术 | `发送添加朋友申请` |
| 指定任务微信或留空 | `任务微信(为空则智能分配)` |

专用执行文件使用 `Sheet1`，并保留空白 `Sheet2`、`Sheet3`。内部达人 ID、蒲公英链接和跟进状态只保留在飞书及内部建联表中。

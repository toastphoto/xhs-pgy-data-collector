# 飞书项目联系人回补与跟进新建：需求草案

整理日期：2026-09-14。依据用户提供的会议文字。需求梳理，不是接口接通或部署验收。
现有导出修复的打包验收仍待进行；本稿不授权真实查询、写入、发送或删除。

同日后续已完成真实 UI 和官方文档只读核验，见[现场报告](FEISHU_LIVE_INSPECTION_2026-09-14.md)。表单显示的必填项是账号昵称、平台、达人资源来源、小红书ID；联系方式当前无必填标记，条件/服务端规则未验证。会议中的联系方式必填不能写死为技术事实。

## 1. 会议明确的业务意图

前置门禁：用户已要求全部上线前测试写入带 AI 测试标志且可清理，见[测试写入与清理规则](FEISHU_PRELAUNCH_TEST_POLICY.md)。未验证可标记和清理能力前，不做任何试写；清理仍须精确列单和当次确认。

- 减少团队库已有联系方式的重复搜索，以及昵称、平台主页等基础资料的重复录入。
- 先用软件选中的达人查询团队库，把可用联系方式补回软件；经确认后，在飞书项目新建本次跟进记录。
- 同一达人可以由不同人员、账号、时间或合作场景分别跟进；查到旧记录不等于禁止新建。
- 本次明确不是覆盖旧记录，也不是按昵称去重、合并或删除别人的记录。
- 未找到联系方式时，保留本地待补名单，支持人工补录后再提交；表格回填为候选辅助路径。
- 蒲公英已完成邀约的记录希望减少手工录入。是否自动提交、何时提交、缺联系方式是否可新建，仍需字段与流程规则确认。

## 2. 必须分开的概念

| 对象 | 含义 | 不应混用 |
| --- | --- | --- |
| 达人身份 | 同一个平台账号/达人 | 昵称并不是稳定主键 |
| 联系方式 | 微信、手机、邮箱及来源 | 后台邀约、待填不是微信号 |
| 跟进记录 | 某负责人/账号/场景的一次业务记录 | 不等于全局唯一达人档案 |
| 邀约结果 | 已确认发送、失败或结果未知 | 已发送不等于建立联系 |
| 同步结果 | 是否确实新建了飞书工作项 | 新建成功不等于自动进入已建联阶段 |

最强反例：两位同事先后跟进同一达人，两次业务新建可以都合法；同一次请求超时后重试产生两条记录则不合法。
因此“允许同一达人多条跟进”与“同一次提交不得重复创建”必须同时满足。

## 3. 建议首期流程（待确认）

1. 用户选择一批达人，执行只读“从团队库补全联系方式”；只访问授权项目和可见字段。
2. 用同平台稳定账号标识或规范化主页匹配。蒲公英与小红书是不同 ID 命名空间，跨平台匹配须已有可信关联；仅昵称相同不自动回填。
3. 显示未匹配、唯一匹配、多条一致、多条冲突、读取失败。相同联系方式可归并来源；多个不同联系方式、身份不确定、本人/经纪人关系不清时由人工选。
4. 在现有复核表中补微信/邮箱/手机，保存来源、原记录引用和查询时间；旧记录更新时间不等于联系方式有效性验证时间。不覆盖用户已确认的非空值，冲突列出差异。
5. 用户确认本批负责人、跟进账号、合作场景与资源来源，查看将新建的字段、缺项及初始流程状态。只有满足已确认业务规则的行进入提交队列。
6. 按批准范围新建飞书项目工作项，回读记录 ID/链接和关键字段。保留本次请求的稳定标识；未知结果先核对，不能直接再次新建。
7. 未匹配或资料未完成者留在本地继续补录。批次进度逐条显示，可继续处理已明确未提交的项，不重做已成功项。

可选表格往返：导出内部稳定行 ID + 基础资料 + 联系方式补录列；导回后按 ID 展示变更预览，仅合并允许编辑的字段。不能靠行号/昵称覆盖，不把整表自动提交飞书。
合作方式切换时替换/删除旧刊例记录是另一套需求，本期不包含。

## 4. 联系方式必填的处理建议（不是已确认字段能力）

- 有可用联系方式：经人工确认满足业务新建条件后，可新建，但不自动认定已建联。
- 无联系方式但邀约确已发送：只有飞书流程明确允许该情况才新建；联系方式类型、渠道和发送结果分开存。
- 若现有必填文本栏必须兼容“后台邀约”，先由管理员确认映射。不能把占位词写进软件的微信字段，更不能交给微信执行导出。
- 无联系方式且未完成邀约：本地待补，不自动用“待填”骗过校验。
- 发送结果未知：待核对；不能以点击过发送按钮当成成功证据。
- “有微信就不再邀约”建议作渠道提示，不等于无需联系，也不剥夺用户选择其他合作渠道。

## 6. 接入前需要的材料

- 真实使用的产品入口与官方文档，确认是飞书项目工作项，不以飞书文档/多维表格接口代替。
- 新建页面和字段配置：字段类型、字段标识、必填/条件必填、选项和关联关系；会议中的“基本都有”不能代替逐字段校验。
- 脱敏样例：同一达人多条记录、有联系、无联系但已邀约，以及创建后初始状态和自动流转规则。
- 查询范围、联系方式共享权限、创建记录的负责人及创建者归属规则。
- 获准的测试项目/记录和最小读取/创建权限。凭据随后在本机安全配置，不放聊天、仓库、导出文件或日志；不把共享长期密钥打包进 EXE。

## 7. 首期验收门槛

- 精确命中可回补；同名不同人不误填；多条冲突不静默任选；用户确认值不被覆盖。
- 未命中/缺必填项不新增垃圾记录；占位文字不能作为有效微信或已联系状态。
- 同一达人不同跟进可各建一条，旧记录不变；同一提交重复点击/超时恢复不多建。
- 已确认发送与未知结果走不同路径；新建不意外推动流程节点。
- 先在授权测试范围完成查询、预览、新建、回读，再讨论全批自动化；权限拒绝、限流和部分成功均须可恢复。

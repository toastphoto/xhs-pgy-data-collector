## 写入前的硬门槛

- 范围包括测试工作项、评论、附件及其他新增测试对象；仅浏览、查询不算业务写入。
- 不在已有真实记录上测试更新，不修改、推进或删除他人的业务记录。需要写入验收时使用获准的独立测试对象。
- 每个对象都带可见的 `[AI测试]` 标志和独立批次号，例如 `AI_TEST_YYYYMMDD_<短随机码>`。工作项使用标题前缀；评论正文和附件名称同样标记。
- 有可用的现有标签/测试字段时，同时保存测试标志、来源和批次。实际字段映射需核实；没有合适字段不得擅自新增或修改团队字段配置。
- 标记必须与首次创建一起写入并回读确认，不能先生成无标识的正式记录，再寄希望于补标。
- 测试标志不能写进微信号、手机号等联系方式字段，也不能伪装成已建联或成功发送。
- 先确认目标空间/工作项类型、标记方案、权限、删除/回收能力和关联对象清理方式。无法可靠标记或确认可清理时，不开始测试写入。
- 先核对创建后自动化、通知和流程流转；可删除记录不意味着可以发送真实邀约、消息或任意推进流程。这些外部影响须单独确认。

## 可追踪与清理

- 每批维护本机受保护、Git 忽略的清单：批次号、测试对象类型/外部 ID、目标定位信息、创建时间、创建/核对/清理状态。不要将真实数据、账号标识、凭据或对象链接写入仓库文档。
- 创建超时或返回不明时，先核对已有对象；不通过重复创建试错，也不能因清单缺失就猜测某条记录归本批所有。
- 清理集合须同时满足：目标空间/类型正确、本批清单记录、AI测试标志与批次匹配。名称包含“测试”本身不足以授权删除。
- 若对象已被他人接手、补充真实业务或出现来源不明的关联，暂停自动清理，先人工核对。
- 清理前给用户预览精确对象清单和数量、删除/回收方式及影响，取得当前确认后执行；永久删除须在动作当时明确确认。
- 清理后重新查询，逐条标记已清理/失败/结果未知；只处理核实属于本批的对象，不遍历删库。
- “可清理”指业务对象可按产品机制删除或回收，不承诺抹除平台审计、安全日志。

## 上线切换

- 正式上线由用户明确确认，不能按日期或一次测试成功自动切换。
- 测试标记不会自动从存量记录移除以伪装成正式数据；存量测试对象继续按清单核对和清理。
- 未来实现须覆盖：无标记拒写、标记回读失败、创建结果未知、重复提交、混入真实记录、他人修改及部分清理失败。

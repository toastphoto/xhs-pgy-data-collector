# UX Redesign Plan

本文件记录桌面端左侧工作台的整体重构方向。目标是在迁移 React/Vue 之前，先用原生 JS 把产品逻辑、信息架构和轻量组件边界打磨清楚。

## 产品定位

蒲公英达人工作台不是浏览器插件，也不是通用 RPA 配置台。它的核心价值是：

1. 找到可能适合的达人。
2. 把候选达人采集成结构化数据。
3. 复核并生成建联表、小蜜蜂导入表、待补联系方式表。

右侧网页区保留给人工登录、搜索、查看达人详情。左侧工作台负责流程、名单、状态、导出和少量诊断。

## 设计原则

- 主流程优先：普通用户第一眼只看到“开始、找达人、复核建联”。
- 渐进披露：采集规则、selector、transform、录制回放、AI 配置默认隐藏在工具箱或高级区。
- 批量操作按需出现：复制、批量改状态、批量导出不常驻，只在筛选/选中后展开。
- 列表 + 详情：复杂表格改成列表显示关键字段，详情/编辑放进展开区或详情面板。
- 少技术词：界面避免 BrowserView、DOM、selector、runDir 等词；无法避免时放入高级维护区。
- 功能不断链：重构 UI 时保留原 IPC 调用和数据结构，先不重写业务逻辑。

## 信息架构

### 1. 开始

用途：让用户知道下一步做什么。

默认展示：
- 三步流程：登录蒲公英、找达人、导出建联表。
- 打开蒲公英入口。
- 检测登录态。
- 跳转找达人、复核建联。

隐藏/弱化：
- 技术检测详情只在检测后展示。

### 2. 找达人

用途：建立候选达人池并开始采集。

推荐结构：
- Step 1：选择来源
  - 导入 Excel。
  - 粘贴链接。
  - 打开蒲公英搜索并加入当前达人。
- Step 2：候选池
  - 默认只展示昵称/链接/状态/优先级。
  - 批量复制、批量标记、导出候选表放入批量处理区。
- Step 3：开始采集
  - 登录态、候选数量、采集范围、规则状态。
  - 主要按钮：开始采集。

高级区：
- 历史任务。
- 搜索筛选条件。
- 渠道和建联口径。
- 采集规则、速度预设。

### 3. 复核建联

用途：把采集结果变成可用建联表。

推荐结构：
- 顶部：当前结果、刷新名单、导出建联表。
- 指标：已选建联、可进小蜜蜂、待补联系方式、当前显示。
- 筛选栏：搜索、状态、联系方式、优先级、跟进状态。
- 达人列表：只展示建联开关、昵称、粉丝/报价摘要、推荐理由、跟进状态。
- 详情编辑：联系方式、备注、排除原因、优先级等放到展开详情或详情面板。

批量操作：
- 当前结果全选/全不选、复制链接、复制摘要、导出当前 Excel、改状态，默认折叠。
- 后续可改为“选中达人后出现 sticky 批量操作条”。

### 4. 工具箱

工具箱包含低频或维护类功能。

#### 采集规则

默认展示：
- 当前规则摘要。
- 更新时间。
- 规则状态。
- 刷新规则。
- 自动识别笔记卡片。
- 测试当前达人页。

高级编辑：
- 规则列表。
- version/platform/mode。
- 字段映射表。
- selector/attr/transform/value。

#### 录制回放

默认展示：
- 说明：仅用于复现操作和排查问题。
- 开始录制、停止保存。
- 当前动作数。
- 最近录制文件卡片。

高级操作：
- 重命名。
- 删除。
- 打开文件夹。

#### AI 分析

默认展示：
- 同步历史数据。
- 数据库/知识库状态。
- 对话框。

高级区：
- API Key、Base URL、模型配置。
- 重建知识库。
- 导出上次筛选结果。

## 轻量组件边界

当前原生 JS 组件层位于 `desktop-app/renderer/ui/components.js`。

已有组件：
- `createPageIntro`
- `createNotice`
- `createActionRow`
- `createButton`
- `createAdvancedSection`
- `createMetricCard`
- `createEmptyState`

建议新增：
- `createStepCard`
- `createSummaryCard`
- `createEntityList`
- `createBulkActionBar`
- `createDetailPanel`
- `createStatusPill`

这些组件未来可平移为 React/Vue 组件。

## 分阶段执行

### Phase 1：全局降噪

- 流程导航替代工程导航。
- 工具箱低频功能折叠。
- 技术词下沉到高级区。

### Phase 2：找达人重构

- 做成三步工作流。
- 历史任务和筛选条件折叠。
- 候选池从表格转列表/卡片。

### Phase 3：复核建联重构

- 默认只显示指标、筛选、达人列表、导出建联表。
- 批量操作按需展开。
- 详情编辑下沉。

### Phase 4：工具箱重构

- 采集规则变成诊断中心。
- 录制回放变成复现工具。
- AI 分析变成报告/问答入口。

## 不变边界

- 不改右侧网页区核心机制。
- 不重写后端采集/导出逻辑。
- 不删除已有数据。
- 不改变现有 Excel 导入/导出 IPC 能力。
- 每轮 UI 改动后运行 `npm test`、`git diff --check`、`python3 scripts/verify_project_memory.py`。

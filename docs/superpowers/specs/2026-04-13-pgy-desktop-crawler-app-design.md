# 2026-04-13 蒲公英完整采集 App（桌面内嵌版）设计稿

## 0. 背景与目标
我们要把现有的“网页采集 + 数据收集”原型，升级为一个**真正可交付的桌面采集 App**：

- **右侧：真内嵌浏览器**（Electron BrowserView），可手工点击/登录/滚动
- **左侧：原生控制台 UI**（不再 iframe 复用旧网页），用于录制/模板/任务/导出/AI 报告
- **默认采集模式：安全模式（DOM 选择器）**
  - 不主动构造接口请求
  - 反爬触发时采用：**暂停队列 → 用户手工介入 → 继续**

### 0.1 v1（第一版可交付）必须包含的模块
用户已确认 v1 必须包含：
1) 录制 & 回放  
2) 采集模板（固定列）  
3) 批量任务（队列、限速、失败续跑）  
4) 导出（JSON/Excel） & AI 数据对比报告  

### 0.2 非目标（v1 暂不做）
- 主动请求接口（自行拼 token/signature 的“爬接口”）
- 自动登录（保存密码/验证码自动处理）
- 高并发采集（并发>1 默认不开放）

## 1. 推荐架构（v1）
采用**Electron + Python(FastAPI)** 的混合架构（落地最快、复用现有后端能力）。

### 1.1 组件划分
- Electron 主进程（`desktop-app/main.js`）
  - BrowserView 作为真内嵌浏览器
  - 启动/管理 Python 后端进程（默认 `127.0.0.1:8010`）
  - 提供 IPC：浏览器控制、录制文件管理、回放执行
- Electron 渲染进程（左侧控制台 UI）
  - 任务编排、模板管理、导出与报告入口
  - 展示队列状态、失败原因与证据包
- BrowserView 页面脚本（`browser_preload.js`）
  - 录制用户行为（click/input/navigation）
  - 生成相对稳定的 selector（v1 先实现基础策略，v1.1 增强）
- Python 后端（`content-analyzer`）
  - 数据模型与存储（任务、结果、证据包）
  - Excel 导出（固定列）
  - AI 对比报告生成（基于固定列口径）

### 1.2 数据流（端到端）
1) 用户在右侧 BrowserView 手工登录蒲公英（profile 持久化）  
2) 用户录制“登录后采集流程” → 生成 recording JSON  
3) 用户导入达人链接列表 → 生成任务队列  
4) 任务执行：
   - 打开 `{{creator_url}}`
   - 回放 recording（不包含登录）
   - 根据模板用 DOM selector 提取数据
   - 保存 raw JSON + 证据包（截图/HTML/错误步骤）
5) 任务完成：导出 Excel（汇总表 + 明细表）  
6) 基于 Excel/JSON 生成 AI 数据对比报告

## 2. 关键产品流程设计

### 2.1 登录态（手工登录 + 记住）
默认策略：**手工登录一次，复用 profile**。  

在 UI 提供：
- 打开蒲公英登录页（在右侧浏览器打开）
- “检测登录态”按钮（基于页面元素/URL 特征）
- “清除登录态”按钮（清空 profile 或新建 profile）

失败规避：
- 遇验证码/风控页：不自动处理，提示用户手工完成

### 2.2 录制与回放（录制的是“登录后流程”）
录制范围：打开达人页后的操作（切 tab / 滚动加载 / 展开模块等）。

**禁止/不建议录制：**
- 登录流程（验证码强不确定）

回放机制：
- 默认“整段回放”
- v1.1 增加“单步调试 / 失败重试 / 步骤跳过”

### 2.3 批量任务（串行 + 失败暂停介入）
默认执行：并发=1，串行队列。

遇到以下情况触发**暂停**：
- 验证码/风控页
- 页面加载失败/数据区域为空
- selector 失效导致关键字段缺失

暂停后：
- 自动产出证据包（截图/HTML/URL/失败步骤）
- UI 引导用户在右侧浏览器手工处理
- 提供按钮：“继续/重试当前步骤/跳过此达人”

## 3. 数据与文件格式（v1）

### 3.1 Recording（动作脚本）格式（JSON）
```json
{
  "createdAt": 1710000000000,
  "meta": {
    "platform": "pgy",
    "mode": "safe_dom",
    "note": "登录后采集流程"
  },
  "actions": [
    { "t": 1710000000100, "type": "navigate", "url": "https://pgy.xiaohongshu.com/..." },
    { "t": 1710000000500, "type": "click", "selector": "...", "text": "..." },
    { "t": 1710000000800, "type": "input", "selector": "...", "value": "..." }
  ]
}
```

### 3.2 Template（采集模板）格式（JSON）
模板由两部分组成：
- `creator_summary`：达人汇总（每达人一行）
- `note_detail`：笔记明细（每笔记一行）

每个字段：
- `name`：列名
- `selector`：CSS selector
- `attr`：可选（提取属性）
- `transform`：清洗规则（数字单位、空值处理、日期规范等）

### 3.3 Result（采集结果）与证据包
每个达人采集输出：
- `raw_result.json`：原始抽取结果（含未清洗字段）
- `normalized_result.json`：规范化后的结果（统一口径）
- `evidence/`：
  - `screenshot.png`
  - `page.html`
  - `error.json`（失败步骤/错误信息/当前URL）

用户已确认：v1 使用默认模板，可在 UI 中增删字段。

### 4.1 达人汇总表（Creator_Summary）
建议字段（以页面可见为准，抓不到的先留空并标记可选）：

### 4.2 笔记明细表（Note_Detail）
- creator_id / creator_name
- note_title
- note_url / note_id
- publish_time
- likes / collects / comments / shares（按页面展示）
- cover_url（可选）
- crawl_time

## 5. AI 数据对比报告（v1）
报告目标：**可对比、可排序、可分层**（偏数据对比）。

建议章节：
1) 概览：样本数、时间范围、失败率、需要手工介入次数  
2) 核心指标对比：粉丝/互动/产能/爆文率（按统一口径）  
3) TOP 榜单：可切换维度（综合评分/爆文/互动等）  
4) 分布与分层：按类目/地区/价格带分组对比（若字段存在）  
5) 异常提示：数据缺失/疑似风控账号列表 + 建议  

说明：综合评分的权重与维度在 v1 先提供默认值，并允许在 UI 中调整（v1.1 增强）。

---

## 6. 反爬与稳定性策略（v1 默认）
### 6.1 行为策略
- 串行执行（并发=1）
- 关键步骤随机等待（可配置范围）
- 自然滚动（分段滚动 + 小停顿）
- 失败即暂停（不硬跑）

### 6.2 环境策略
- 持久 profile（手工登录 + 记住）
- 不自动登录、不保存密码
- 默认不启用代理（代理做可选项）
